# AGENTS.md — @aggc/ui

Vue 3 component library with PandaCSS. Ships primitives, recipes, layouts, patterns, and design tokens as `@aggc/ui` on npm.

---

## Quick Commands

```bash
npm run panda:codegen        # regenerate styled-system/ (auto-runs in most scripts)
npm run typecheck             # vue-tsc --noEmit
npm run test                  # Vitest unit tests (jsdom)
npm run build                 # Vite lib build + types + assets + package check
npm run docs                  # Storybook dev on :6006
npm run docs:build            # build static Storybook
npm run test:visual           # builds Storybook → Playwright visual regression (~4 min)
npm run test:visual:update    # regenerate visual snapshots
```

CI pipeline: `typecheck` → `test` → `build` → `docs:build`

---

## Branching — OBLIGATORIO

- Toda rama parte de `main`, se borra tras el merge.
- **⛔ Prohibido:** `develop`, `staging`, `release`, `dev`, `stage` y cualquier variante. Los squash merges crean SHAs nuevos → estas ramas divergen de `main` → conflictos irresolubles.
- Un GitHub Action borra automáticamente cualquier rama con esos nombres si se crea en remote.
- Alternativa para staging: PR draft hacia `main`.

## Project Structure

```
src/
  components/          ← Vue components (triplet: .vue + .styles.ts + .test.ts)
  styles/
    primitives/        ← surfaces, typography, fields, feedback
    recipes/           ← variant-driven cva() recipes (button, badge, card, input, dropdown)
    layouts/           ← page, stack, cluster, split
    patterns/          ← pageHeader, emptyState, metricGrid, actionToolbar…
  tokens/              ← colors, spacing, radius, typography, motion
  stories/             ← Storybook stories (Primitives / Forms / Feedback / Layout)
  css/                 ← CSS entrypoints (base, fonts, storybook)
  test/                ← test setup (Vitest)
tests/visual/          ← Playwright visual regression tests + __screenshots__/
styled-system/         ← AUTO-GENERATED by panda:codegen — NEVER edit
examples/vue-consumer/ ← integration smoke test
```

**Path aliases** (tsconfig + vite + storybook):

- `@/` → `src/`
- `@styled/` → `styled-system/`

## Architecture Rules

### Styles MUST live in `.styles.ts`, never in `.vue`

PandaCSS uses static analysis — it cannot scan Vue SFCs.

- No `css()`, `cva()`, or `@styled/css` imports inside `.vue` files
- No `:style=` bindings unless truly runtime-computed
- All style exports go in `ComponentName.styles.ts`, imported by `ComponentName.vue`

### Style composition order

1. Shared recipe from `src/styles/recipes/` if one exists
2. Shared primitives/layouts/patterns from `src/styles/`
3. Component-specific overrides in `ComponentName.styles.ts`
4. Never duplicate logic already in a shared recipe

### Semantic tokens only

- Colors: `text.primary`, `bg.card`, `border.accent` — never raw hex/rgb
- Spacing: Panda scale keys (`"2"`, `"4"`, `"3.5"`) — never px values
- Dark mode: `data-theme="dark"` on root → Panda condition `_dark`

## Component Conventions

### Naming

- `UiXxx` for primitives (UiButton, UiSelect, UiCheckbox…)
- Bare descriptive names for layout/pattern components (SectionCard, ResultPanel, PageSurface…)

### Triplet pattern

Every component = 3 files:

```
ComponentName.vue          ← script setup + template
ComponentName.styles.ts    ← all css()/cva() calls
ComponentName.test.ts      ← unit tests (ARIA, props, slots)
```

### Props policy (closed set)

Only these visual props are allowed:

| Prop                   | Example                                                     |
| ---------------------- | ----------------------------------------------------------- |
| `variant`              | `'solid' \| 'outline' \| 'subtle'`                          |
| `size`                 | `'sm' \| 'md' \| 'lg'`                                      |
| `tone`                 | `'default' \| 'info' \| 'success' \| 'warning' \| 'danger'` |
| `disabled` / `loading` | `boolean`                                                   |

**Never add:** `padding`, `color`, `background`, `width`, `margin`, `className`, `style`.

### Accessibility

- `aria-disabled` on disabled interactive elements
- `aria-busy="true"` on loading states
- `aria-expanded`, `aria-controls` on dropdowns
- Keyboard navigation for all interactive primitives
- `focus-visible` outline (global CSS handles this)

### Export

Add every new component to `src/components/index.ts`.

## Testing

### Unit (Vitest)

- Co-located: `src/components/ComponentName.test.ts`
- Test: ARIA attributes, prop→DOM mapping, slots, state combinations
- Don't test: CSS class names, visual appearance

### Visual (Playwright)

- Location: `tests/visual/`
- Runs against Storybook iframe routes built fresh each time
- After intentional visual changes: `npm run test:visual:update` then commit `__screenshots__/`
- First-time snapshots must be generated before `test:visual` will pass

---

## Storybook

- Location: `src/stories/{category}/ComponentName.stories.ts`
- Categories: `primitives/` → `forms/` → `feedback/` → `layout/`
- Always wrap in `StoryThemeFrame` for light/dark toggle
- CSF3 format, `tags: ['autodocs']`, render-function based
- Source snippets go in `src/stories/support/sources.ts`
- Support utilities: `StoryThemeFrame.vue`, `storyStyles.ts`

## Release (Changesets)

1. `npx changeset` — select `@aggc/ui`, pick bump type, write consumer-facing summary
2. Commit `.changeset/*.md` with the code
3. Merge to `main` → CI opens "Version Packages" PR
4. Merge that PR → auto-publishes to npm

**Bump guide:**

- `patch` — bug fix, no API change
- `minor` — new component, new variant/prop, new export
- `major` — breaking change to component API, removed exports

**Never:** manually edit `package.json` version or `CHANGELOG.md`, or run `npm publish` directly.

**No changeset needed for:** `.claude/`, `.storybook/`, `tests/`, `src/stories/`, docs, tooling-only changes.

---

## Critical Don'ts

| ❌ Rule                                  | Why                                                    |
| ---------------------------------------- | ------------------------------------------------------ |
| `css()`/`cva()` in `.vue` files          | Panda misses classes → styles silently missing in prod |
| Raw hex/rgb/px values                    | Breaks theming and dark mode                           |
| `npm publish` directly                   | Bypasses Changesets version tracking                   |
| Ad-hoc visual props on components        | Breaks published API contract                          |
| Edit files in `styled-system/`           | Overwritten on next `panda:codegen`                    |
| Import from `styled-system/css` directly | Use `@styled/css` alias                                |

## Tech Stack

- **Vue 3** (Composition API, `<script setup>`)
- **PandaCSS** (static CSS extraction, semantic tokens, `cva`/`css`)

- **TypeScript 5** (strict mode)
- **Vitest** (unit tests, jsdom)
- **Playwright** (visual regression against Storybook)
- **Storybook 9** (component docs, Vue 3 + Vite)
- **Changesets** (versioning and npm publish)
- **Icons:** `lucide-vue-next` only
- **Fonts:** IBM Plex Sans (body), Space Grotesk (display)
- **Node:** ≥18.18.0
